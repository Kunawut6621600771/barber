# ระบบเรียกคิวร้านตัดผม (Barbershop Queue Management System)

ระบบจัดการคิวร้านตัดผมแบบครบวงจร พัฒนาตาม Requirement ในเอกสาร `IT_requirement.pdf`

**Objective** — บริหารจัดการคิวลูกค้าอย่างเป็นระบบ ลดเวลาการรอคิว ลดความผิดพลาดในการเรียกคิว
เพิ่มความสะดวกให้ทั้งลูกค้าและพนักงาน และติดตามสถานะคิวได้แบบ **Real-time**

นอกจากระบบคิวแล้ว ยังมี **POS ขายหน้าร้าน** (สินค้า สต็อก กะเงินสด ใบเสร็จ คืนเงิน),
**สมาชิกสะสมแต้ม**, **จองคิวล่วงหน้า** และ **LINE Bot** ที่ตอบคำถามลูกค้าได้เองตลอด 24 ชั่วโมง
รองรับทั้งโหมดสว่างและโหมดมืด

## การติดตั้ง

### 1. ติดตั้ง PostgreSQL

**วิธีที่ใช้อยู่ตอนนี้ — Docker** (container ชื่อ `barbershop-db` ถูกสร้างไว้แล้ว)

```bash
docker run --name barbershop-db -e POSTGRES_PASSWORD=postgres -p 5440:5432 -d postgres:16
```

ครั้งต่อไปแค่สั่งให้ container เดิมทำงานอีกครั้ง:

```bash
docker start barbershop-db
```

หรือถ้าอยากติดตั้งลงเครื่องตรง ๆ ดาวน์โหลดจาก <https://www.postgresql.org/download/windows/>
(จำรหัสผ่านของ user `postgres` ที่ตั้งไว้ตอนติดตั้งด้วย แล้วแก้ `PGPASSWORD` ใน `.env` ให้ตรง)

> **เรื่องเขตเวลา** — PostgreSQL ใน Docker รันเป็น UTC ซึ่งทำให้ `CURRENT_DATE` ไม่ตรงกับ
> "วันนี้" ของประเทศไทย ระบบจึงบังคับ timezone ของทุก session ให้เป็นค่า `SHOP_TIMEZONE`
> ใน `.env` (ค่าเริ่มต้น `Asia/Bangkok`) และคำนวณ "วันนี้" ฝั่ง Node ด้วยเขตเวลาเดียวกัน
> ถ้าย้ายร้านไปเขตเวลาอื่น ให้แก้ค่านี้ค่าเดียว

### 2. ตั้งค่า Backend

```bash
cd backend
npm install
```

คัดลอก `.env.example` เป็น `.env` แล้วแก้ `PGPASSWORD` ให้ตรงกับรหัสผ่าน PostgreSQL ของคุณ

```bash
copy .env.example .env
```

### 3. สร้างฐานข้อมูล + ใส่ข้อมูลตัวอย่าง

```bash
npm run db:setup
```

สคริปต์นี้จะสร้าง database `barbershop` แล้วรัน `schema.sql` และ `seed.sql` ให้อัตโนมัติ
(ถ้าไม่ต้องการข้อมูลตัวอย่าง ใช้ `npm run db:setup -- --no-seed`)

หรือรันด้วย `psql` เองก็ได้:

```bash
psql -U postgres -c "CREATE DATABASE barbershop"
psql -U postgres -d barbershop -f ../database/schema.sql
psql -U postgres -d barbershop -f ../database/seed.sql
```

### 4. เริ่มใช้งาน

เปิด **2 terminal**

```bash
cd backend
npm run dev
```

```bash
cd frontend
npm install
npm run dev
```

เปิดเบราว์เซอร์ที่ <http://localhost:3000>

> **หมายเหตุสำหรับ Windows** — ถ้า `npm install` ที่ frontend ขึ้น error
> `ERR_INVALID_ARG_TYPE ... "file" argument must be of type string`
> แปลว่าตัวแปรระบบ `ComSpec` หายไป ให้รันคำสั่งนี้ก่อนใน PowerShell:
> `$env:ComSpec = "$env:SystemRoot\System32\cmd.exe"`

## โครงสร้างฐานข้อมูล

**ตาราง**

| ตาราง | หน้าที่ |
|-------|--------|
| `users` | ผู้ใช้ทุกบทบาท + ค่าตั้งการแจ้งเตือน |
| `refresh_tokens` | เซสชันการเข้าสู่ระบบ (ใช้ตอน Logout) |
| `password_resets` | token สำหรับ Forgot / Create Password |
| `barbers` | ข้อมูลช่างตัดผม (ขยายจาก `users`) |
| `service_categories`, `services` | ประเภทบริการ และบริการ (ระยะเวลา + ราคา) |
| `barber_services` | ช่างคนไหนทำบริการอะไรได้ |
| `queue_tickets` | บัตรคิว (หัวใจของระบบ) |
| `queue_events` | ประวัติการเปลี่ยนสถานะคิว ใช้ทำรายงาน |
| `notifications` | การแจ้งเตือนของผู้ใช้ |
| `shop_settings` | ค่าคอนฟิกร้าน เช่น เกณฑ์แจ้งเตือนใกล้ถึงคิว |

**Function**

- `next_ticket_no(date)` — ออกเลขคิวอัตโนมัติ รีเซ็ตทุกวัน ใช้ advisory lock กันเลขชนกัน
- `reorder_queue(date)` — จัดลำดับคิวอัตโนมัติ (`priority` → คิวที่ถูกข้ามน้อยกว่า → เวลารับบัตร)
- `estimate_wait_minutes(date, position)` — ประมาณเวลารอจากบริการที่ค้างอยู่หารด้วยจำนวนช่าง

**View**

- `v_queue_board` — คิวพร้อมข้อมูลลูกค้า บริการ และช่าง (ใช้แทบทุกหน้าจอ)
- `v_daily_stats` — สถิติรายวัน (จำนวนคิว เวลารอเฉลี่ย รายได้)
- `v_barber_performance` — ผลงานของช่างแต่ละคน

**ข้อจำกัดสำคัญที่บังคับในระดับฐานข้อมูล**

- ลูกค้า 1 คน มีคิวที่ยัง active ได้แค่ 1 ใบต่อวัน (partial unique index)
- เลขคิวและลำดับห้ามซ้ำภายในวันเดียวกัน
- แจ้งเตือนชนิด `near_turn` / `your_turn` / `cancelled` ยิงซ้ำต่อคิวไม่ได้

## หมายเหตุด้านความปลอดภัย

- รหัสผ่านเก็บด้วย bcrypt (cost 10) ไม่เก็บ plaintext
- refresh token เก็บเป็น SHA-256 hash ในฐานข้อมูล
- เปลี่ยนรหัสผ่าน / รีเซ็ตรหัสผ่าน จะเพิกถอนทุกเซสชันเดิม
- ข้อความตอนล็อกอินผิดเหมือนกันทั้งกรณีอีเมลผิดและรหัสผ่านผิด (กันการเดาว่ามีอีเมลนี้ในระบบ)
- ทุก query ใช้ parameterized statement ป้องกัน SQL injection
- ก่อนใช้งานจริง: ตั้ง `JWT_SECRET` เป็นค่าสุ่มยาว ๆ และเปลี่ยนรหัสผ่านบัญชีทดสอบทั้งหมด

## สิ่งที่ยังไม่ได้ต่อของจริง

- **การส่งอีเมล** — ลิงก์รีเซ็ตรหัสผ่านยัง `console.log` ไว้ฝั่ง server (และส่งกลับมาแสดงบนหน้าจอเฉพาะโหมด dev)
  ถ้าจะใช้จริงให้ต่อ SMTP/SendGrid ที่ `backend/src/controllers/auth.controller.js` ฟังก์ชัน `forgotPassword`
- **SMS** — โครงสร้าง `notifications.channel` รองรับไว้แล้ว จุดต่อคือ `backend/src/utils/notify.js`

## ชำระเงิน QR PromptPay + LINE Bot / LIFF

- ลูกค้าเลือกบริการ → สแกน QR PromptPay ตามราคา → อัปโหลดสลิป → ตรวจอัตโนมัติ (EasySlip) → ได้บัตรคิว
- พนักงานดู/ยืนยันการชำระเงินได้ที่เมนู **การชำระเงิน**
- LINE Official Account แจ้งเตือนใกล้ถึงคิว / ถึงคิว / ชำระเงินสำเร็จ และเปิดแอปในไลน์ผ่าน LIFF (`/liff`)

อัปเดตฐานข้อมูลเดิมด้วย `npm run db:migrate` แล้วดูวิธีตั้งค่าทั้งหมดใน
[docs/LINE_PROMPTPAY_SETUP.md](docs/LINE_PROMPTPAY_SETUP.md)

## POS — ขายหน้าร้าน

บิลหนึ่งใบมีได้ทั้งค่าบริการ (ตัดผม) และสินค้า (แว็กซ์ แชมพู) จ่ายได้หลายวิธีในบิลเดียว
ระบบตัดสต็อก สะสมแต้ม และปิดคิวที่ผูกไว้ให้อัตโนมัติเมื่อชำระเงินเสร็จ

**ขั้นตอนใช้งานประจำวัน**

1. **เปิดกะ** (`/app/shifts`) — นับเงินทอนในลิ้นชักแล้วกรอกตามจริง
2. **ขาย** (`/app/pos`) — เปิดบิล → กดการ์ดบริการ/สินค้า → ใส่ส่วนลดหรือแต้ม → ชำระเงิน → พิมพ์ใบเสร็จ
3. **ปิดกะ** — นับเงินจริง ระบบเทียบกับยอดที่ควรมีแล้วบอกว่าขาดหรือเกินเท่าไร

**ความสามารถ**

| เรื่อง | รายละเอียด |
|---|---|
| เปิดบิล | จากคิวที่กำลังให้บริการ (ดึงบริการ+ช่างมาให้) · จากสมาชิก · หรือลูกค้าทั่วไป |
| ส่วนลด | กรอกเป็นบาท/เปอร์เซ็นต์ หรือใช้โค้ดส่วนลดที่ตั้งไว้ (มีเพดานส่วนลด ยอดขั้นต่ำ วันหมดอายุ จำนวนครั้ง) |
| แต้มสะสม | ใช้แต้มแทนเงินได้ มีขั้นต่ำต่อครั้ง และได้แต้มคืนจากยอดสุทธิ |
| ชำระเงิน | เงินสด / QR พร้อมเพย์ / บัตร / โอน — **แยกจ่ายหลายวิธีในบิลเดียวได้** คำนวณเงินทอนจากเงินสดเท่านั้น |
| ใบเสร็จ | แสดงบนจอและสั่งพิมพ์กระดาษความร้อน 80 มม. ได้ทันที (`@media print`) |
| ยกเลิก / คืนเงิน | ยกเลิกบิลที่ชำระแล้วทำได้เฉพาะ admin และต้องระบุเหตุผล · คืนเงินบางส่วนหรือเต็มจำนวน พร้อมคืนของเข้าสต็อก |
| กันขายเกินสต็อก | นับรวมของที่ค้างอยู่ในบิลอื่นที่ยังเปิดด้วย และล็อกแถวสินค้าตอนตัดสต็อกจริง |

**หน้าจอที่เกี่ยวข้อง**

| เส้นทาง | คำอธิบาย |
|---|---|
| `/app/pos` | หน้าขาย — แคตตาล็อก + ตะกร้า + ชำระเงิน |
| `/app/sales` | ประวัติบิล · ดูใบเสร็จย้อนหลัง · คืนเงิน · ส่งออก CSV |
| `/app/products` | สินค้าและสต็อก · รับของเข้า · ตัดของเสีย · ประวัติการเคลื่อนไหว |
| `/app/shifts` | เปิด/ปิดกะ · เงินเข้า-ออกลิ้นชัก · สรุปขาด/เกิน |
| `/app/members` | สมาชิก แต้มสะสม ระดับสมาชิก · ปรับแต้มด้วยมือ (admin) |
| `/app/settings` | ตั้งค่าร้าน (ชื่อ ที่อยู่ เวลาเปิด-ปิด ภาษี แต้ม) + จัดการโค้ดส่วนลด |
| `/app/book` | จองคิวล่วงหน้า — ลูกค้าเลือกช่วงเวลา พนักงานกดเช็กอินเพื่อออกบัตรคิว |

**ระดับสมาชิก** คำนวณจากยอดใช้จ่ายสะสมอัตโนมัติ: Bronze → Silver (฿4,000) → Gold (฿12,000) → Platinum (฿30,000)

## LINE Bot — ผู้ช่วยตอบลูกค้า

บอทตอบลูกค้าได้เองตลอด 24 ชั่วโมง โดยดึงข้อมูลจริงจากฐานข้อมูลมาตอบ
ตรรกะอยู่ที่ [backend/src/utils/line-bot.js](backend/src/utils/line-bot.js) และการ์ด Flex อยู่ที่
[backend/src/utils/line-flex.js](backend/src/utils/line-flex.js)

| ลูกค้าพิมพ์ | บอทตอบ |
|---|---|
| คิวของฉัน / ถึงคิวยัง | หมายเลขคิว สถานะ เหลืออีกกี่คิว รอประมาณกี่นาที ช่างที่ดูแล |
| คิวตอนนี้ / รอนานไหม | คิวที่กำลังเรียก กำลังให้บริการ จำนวนคิวที่รอ และเวลารอโดยประมาณ |
| ราคา / ตัดผมเท่าไหร่ | การ์ดเลื่อนได้แสดงบริการทั้งหมดพร้อมราคาและเวลาที่ใช้ |
| ร้านเปิดกี่โมง | เวลาทำการตามที่ตั้งไว้ในหน้าตั้งค่าร้าน |
| ร้านอยู่ไหน / ขอเบอร์ | ที่อยู่ ปุ่มเปิดแผนที่ และปุ่มโทรหาร้าน |
| มีช่างกี่คน | รายชื่อช่างที่อยู่ร้านวันนี้พร้อมสถานะว่าง/ไม่ว่าง |
| แต้มของฉัน | แต้มคงเหลือ ระดับสมาชิก และอีกเท่าไรจะเลื่อนระดับ |
| มีโปรอะไรบ้าง | โค้ดส่วนลดที่ยังใช้ได้จริงในตอนนั้น |
| จ่ายยังไงได้บ้าง | ช่องทางชำระเงินทั้งหมดของร้าน |
| จองคิว | ลิงก์เปิดหน้าจองล่วงหน้าใน LIFF |
| ขอยกเลิกคิว | พาไปยืนยันในแอปอีกชั้น (กันกดพลาดจากในแชท) |
| ประวัติการตัด | 5 ครั้งล่าสุดและยอดสะสม |
| แอดมิน | บันทึกข้อความไว้ให้พนักงาน + แจ้งเบอร์ร้าน |

**ผูกบัญชีด้วยการสแกน QR** — หน้าชำระเงิน หน้าหลังรับบัตรคิว และหน้าคิวของฉัน จะมี QR ให้ลูกค้าสแกน
สแกนแล้วไลน์จะเปิดห้องแชทร้านพร้อมข้อความที่มีรหัส กดส่งครั้งเดียวเป็นอันผูกบัญชีเสร็จ
หน้าเว็บอัปเดตเป็น "เชื่อมแล้ว" เองโดยไม่ต้องรีเฟรช จากนั้นจะได้แจ้งเตือน **ใกล้ถึงคิว** และ **ถึงคิว** ในแชท
(ใช้ได้แม้ลูกค้าเปิดเว็บบนคอมพิวเตอร์ของร้าน — ต้องตั้ง `LINE_BOT_BASIC_ID`)

คำที่บอทไม่เข้าใจจะตอบพร้อมเมนูแนะนำ ไม่ปล่อยเงียบ
ทุกข้อความถูกบันทึกไว้ในตาราง `line_messages` ให้พนักงานตามอ่านย้อนหลังได้
(`GET /api/line/threads`, `GET /api/line/messages`) และตอบกลับผ่าน `POST /api/line/push`

**เมนูด้านล่างห้องแชท (rich menu) 6 ปุ่ม**

```bash
cd backend
npm run line:richmenu:image   # สร้างรูปเมนูใหม่ (อ่านชื่อร้านจากฐานข้อมูล)
npm run line:richmenu         # อัปโหลดขึ้น LINE OA แล้วตั้งเป็นเมนูหลัก
```

## ความปลอดภัยฝั่งเซิร์ฟเวอร์

- `helmet` ตั้ง security headers · `compression` บีบอัด response
- Rate limit: ล็อกอิน 20 ครั้ง/15 นาที · สมัครสมาชิกและลืมรหัสผ่าน 10 ครั้ง/ชม. · API รวม 600 ครั้ง/นาที
  (ยกเว้น SSE ที่เปิดค้างไว้ตลอด)
- ทุกการแก้ยอดเงิน สต็อก และแต้ม ทำใน transaction เดียวพร้อม `SELECT ... FOR UPDATE`
